    Help and Support¶

    Start here when something does not work, or when you do not know where to look. This guide is for the cluster administrator who runs the driver.

    1. Where to start¶

    Open the IBM VPC File Pools page in the OpenShift console. Each tab has one job:

    Console tab What it is for Guide
    Overview Pool capacity, latency and alerts at a glance MONITORING.md
    Pools Make and change pools of shared storage TUTORIAL-01-POOL-CREATION.md, CAPACITY-PLANNING.md
    SubVolumes The volumes (PVCs) held in the pools USER-GUIDE.md
    Snapshots Snapshots of volumes and of VM disks, and restore TUTORIAL-02-SNAPSHOTS-AND-CLONES.md, VM-INSTANT-SNAPSHOTS.md
    Replication Copies of volumes and running VMs to a second cluster TUTORIAL-06-REPLICATION-AND-FAILOVER.md, CROSS-REGION-DR.md
    Monitoring Graphs of the driver's metrics MONITORING.md

    Backups of volumes and VMs are set up with BackupPolicy and used with the kubectl backup command: see BACKUP-RECOVERY.md.

    2. Common problems¶

    What you see Go to
    A PVC stays Pending PVC Issues
    A pool is full Pool Full — maxShares reached
    A VM does not start VM Issues
    A VM does not start after a snapshot VM with instant snapshots does not start
    A pod cannot mount its volume Mount Issues
    Replication is late or failing Replication is late or failing
    Backups stopped Backups stopped: the snapshot pool is above 85% full
    A volume has no recent backup A volume has no recent backup
    The driver itself will not start Controller Issues
    VPC errors (403, quota, rate limit) VPC API Issues

    Five commands to run first are in the Quick Diagnostic Checklist.

    3. Collect diagnostics for a support case¶

    bash scripts/collect-diagnostics.sh

    This writes csi-diagnostics-<time>.txt in the current directory. It holds: - the driver version and the cluster version, - the pools, volumes, snapshots, backup policies, backup restores and replication policies, - the driver pods, the controller log (500 lines), the node logs (200 lines per node) and recent events.

    It reads no Secret, so it holds no API key. It also removes values that look like keys, tokens or passwords. Read the file before you send it. Set NS=<namespace> if the driver is not in kube-system.

    4. Get support¶

    Open an issue in the project repository and attach the diagnostics file: https://github.com/neil1taylor/ibm-vpc-file-pool-csi/issues

    Say in the issue: - the cluster type (ROKS or ROVS) and its version, - the driver version (the image tag), - what you did, what you expected and what happened, - the diagnostics file.

    5. Known limits¶

    • KNOWN-LIMITATIONS.md lists what the driver cannot do.
    • FEATURES.md shows the maturity of each feature. A feature marked Experimental can change, and you should test it before you rely on it.
