Instant VM Snapshots

A VM's disk is one file, disk.img, on a shared file share. An instant snapshot copies nothing. QEMU, the program that runs the VM, stops writing to the disk's file and writes to a new, small file next to it. This set of files is a chain. Each block below is one piece of the disk. The letter is what is stored in it.

Settings

Driver setting vmSnapshots.method
KubeVirt Sidecar feature gate
Snapshots of VM disks are

The Sidecar feature gate is a switch in KubeVirt. It is off by default. It lets a VM's pod have an extra container. The driver setting vmSnapshots.enableSidecarGate=true turns the gate on after each install and upgrade. It needs method=auto. You can also turn the gate on by hand. Nothing in the driver ever turns the gate off: you do that by hand.

Try: take a snapshot, then change data. The snapshot keeps the old letters. The VM sees the new ones. Then stop and start the VM. Then turn the gate off and start the VM again. A block with a white outline was just changed.

What to know

  • Reads: QEMU looks in the newest file first. If that piece is not there, it looks in the file before, down to disk.img. Each file has a small map of the pieces it holds, so this is fast.
  • Taking a snapshot of a running VM: the guest is frozen for a moment, so it writes its pending data to disk. OpenShift does this when you take a VM snapshot in the console. Otherwise the driver asks the guest agent. QEMU then starts the new file, and the guest thaws. The VM never stops.
  • Frozen files are read-only. A write to a frozen file would damage every snapshot built on it.
  • The hook: KubeVirt always opens disk.img when a VM starts. It does not know about the chain. So when a VM with snapshots starts, the driver adds a hook: a small extra container in the VM's pod. The hook tells QEMU to open the newest file. The hook needs the Sidecar gate. A running VM does not need the hook to take a snapshot or to move.
  • Fail safe: if a VM with snapshots starts without the hook, QEMU cannot write to the read-only disk.img, so the VM does not start. It never starts on old data.
  • To turn instant snapshots off: delete each VM's snapshots first (kubectl pool-snapshots flatten <vm> -n <namespace>), then turn the gate off.
  • A stopped VM: QEMU does not run, so a Job makes the new file or does the merge. While the Job runs, the VM cannot start.
  • Deleting a snapshot merges the next file into it. Only the changed pieces move. Restoring makes a new disk with a full copy, so it is not instant.
  • Limits: the driver allows at most 16 snapshot files per disk, because each file makes reads a little slower. This page allows 5.
  • Support: Red Hat does not support the Sidecar gate. With it on, HyperConverged reports TaintedConfiguration=True. The gate is for the whole cluster: anyone who can create or edit a VM can then add an extra container to that VM's pod.
