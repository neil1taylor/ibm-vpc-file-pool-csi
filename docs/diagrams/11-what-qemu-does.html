What QEMU Does

QEMU is the program that runs each VM. It runs in the VM's pod, in the container called compute. It reads and writes the VM's disk file, disk.img, on the share. The driver does not run VMs. It sends commands to QEMU when it needs a copy of a running VM's disk. This page shows one disk of 12 blocks. The number in a block is its version. The version goes up each time the guest writes to that block.

What the driver asks QEMU to do

  • Copy all the disks of a VM at one moment. Replication, backup to COS and snapshots of a running VM use this copy.
  • Keep a change list. A change list records which blocks the guest wrote after a copy started. The next copy then holds only those blocks.
  • Start a new file for an instant snapshot, and merge files when you delete a snapshot. The snapshot chain page shows this.

The driver sends these commands with virsh in the compute container. Red Hat does not support commands sent to QEMU in this way. When the VM is stopped, QEMU does not run, so the driver works on the files with Jobs.

Try this: start a copy, let the guest write, and let QEMU copy until it is done. Then write some more and start a second copy. Then start a third copy and move the VM while it runs.

What to know

  • When a copy starts, the guest is frozen for about 0.15 seconds. The freeze makes the guest write its pending data to disk. It needs the guest agent in the VM. Without the guest agent, the copy is only crash consistent: the same as the disk after a power cut.
  • QEMU writes the copy to a staging file: a file next to disk.img on the same share. Its name starts with .repl-staging-.
  • If the guest writes a block that QEMU has not copied yet, QEMU first copies the old block. So the copy always shows the moment it started, even while the guest writes.
  • QEMU copies slowly on purpose, 20 MB/s for each disk by default, so the VM keeps its speed. You can change the limit.
  • The speed limit also counts the empty parts of a disk. So a large disk takes time even when it holds little data.
  • The change list is only in QEMU's memory. If the VM moves to another node or restarts, a new QEMU starts with no change list. The next copy is then a full copy.
  • A live migration fails while QEMU copies. So when a move starts, the driver stops the copy and deletes the staging file. The move then goes ahead.
  • Only one copy runs in a VM at a time.

Lab results, rovslab, 20 October 2026: the freeze paused the guest for 0.15 to 0.17 seconds. With no speed limit, the guest wrote 10 to 20 times slower during a copy. At 20 MB/s it kept almost all its speed. A 20 GiB disk with 2 GB of data took about 18 minutes at 20 MB/s.
