Replication to another cluster

Replication keeps a copy of your volumes in another cluster, so you can start your work there if the first site is lost. A small receiver runs in the other cluster. Every so often, the source cluster sends its volumes to the receiver. Press Next step to follow one copy.

    Plain files and VM disks travel differently

    Plain volume: a Job tars the folder and uploads it over HTTPS. With a receiver, the whole folder is sent each cycle. (With a direct NFS link and no receiver, rsync sends only changed files.) The destination keeps the latest copy.

    VM disk: the guest is frozen for an instant and QEMU copies all the VM's disks at one moment. The first time, everything is checked against the receiver, and only pieces that differ cross the network (the check uses a hash of each 64 KiB chunk). Later copies hold only the changed blocks. Before the receiver writes, it saves the old blocks in an undo file. Those undo files are the restore points.
