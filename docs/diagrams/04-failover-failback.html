Failover and Failback

Replication keeps copies of a VM's disks at a second site, the DR site. If the main site is lost, a person runs kubectl failover and the VM starts at the DR site from the newest moment that all its disks can show. Failback is going home again later. Nothing here is automatic: a person decides.

2. Lose the main site (needs 2 copies):

Copies arrive every 15 minutes in this example (the real schedule is yours to set). Each copy holds all of the VM's disks at one moment. The times are made up.

The plan · kubectl failover plan

By default the VM starts from the newest moment all its disks can show. To start earlier, choose a restore point (--rewind-to). Restore points reach back as far as the policy keeps them: 24 hours by default.

Failback · going back to the main site

  1. Create a ReplicationPolicy on the DR cluster that points back to the original region.
  2. Let it sync the data from the DR site to the main site.
  3. Shift the workloads back.

This is all the documentation says (CROSS-REGION-DR.md). There is no failback command, and it has not been tested in the lab the way failover has.
